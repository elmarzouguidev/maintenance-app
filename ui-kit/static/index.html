Reference kit

UI kit · {{ brand }}

Every layout, component and pattern of the interface, with fictional data. Blade + Alpine.js + Tailwind CSS v4. Rules: REFERENCE.md. Rebranding: BRANDING.md.

Foundations

Tokens, icons and display formats every component is built on.

  • Design tokens Colours, type scale, radius, elevation and motion: the only values a view may use.
  • Icons The 51 inline Heroicons v2 outline icons of x-admin.icon.
  • Display formats Amounts, dates, plates and durations: one format everywhere, tabular figures.

Components

Every x-admin.* Blade component with its variants and states.

  • Buttons x-admin.button and x-admin.icon-button.
  • Alerts and messages x-admin.alert, flash messages (x-messages) and the validation summary (x-messages.errors).
  • Status badges x-admin.status-badge and x-admin.badge: the single status colour mapping.
  • Stats cards x-admin.stats-card in x-admin.stats-grid: key figures, filters and links.
  • Page header x-admin.page-header: the one visible title of a page.
  • Detail page x-admin.detail-page, x-admin.detail-section, x-admin.detail-item: hairline sections on the white page.
  • Empty states x-admin.empty-state for an empty list, search or panel.
  • Tables x-admin.table: compact rows, hairlines, horizontal scroll inside the panel.
  • Text fields x-admin.form-input and x-admin.textarea, on the shared field wrapper.
  • Choices x-admin.form-select, x-admin.form-select2, x-admin.segmented-radio, checkbox and switch.
  • Date picker x-admin.date-picker: date, date and time, time only, native on phones.
  • File upload x-admin.file-upload: drop zone with previews.
  • Settings fields x-admin.setting-field: one settings field of any type.
  • Modal dialogs x-admin.modal: native dialog with focus trap, Escape and focus return.
  • Delete action x-admin.delete-action: confirmed deletion, or the reason it is refused.
  • Navigation x-admin.nav-link, sidebar groups, section tabs and pagination links.
  • Guest heading x-admin.guest-heading: logo and title of sign-in pages.

Domain components

Optional, vehicle-rental specific. Keep them only in projects that need them.

  • Vehicle condition map x-admin.vehicle-condition-map and x-admin.vehicle-top-view: damage zones at check-out and check-in. Optional domain component.

Patterns

CSS-only kit classes (no Blade component): surfaces, menus and overlays.

  • Surfaces admin-card, admin-card-soft, admin-inset, admin-filter-card and admin-popover.
  • Menus and popovers Dropdown menus: admin-popover with admin-menu-item, Alpine toggles and Escape.
  • Drawer and bottom sheet admin-drawer and admin-sheet: native dialogs for navigation and phone choices.

Layouts

The four shells, with the app layouts and fictional content.

  • Tenant shell Dark brand sidebar, topbar with context switcher, search, notifications and account menu, footer, phone bottom bar.
  • Tenant shell, restricted member The same shell for a member with few permissions: hidden navigation items, one organisation, no notifications.
  • Phone field screen A phone-first screen (check-out, check-in): 44 px controls, sticky action bar, no bottom bar.
  • Platform shell Super-admin shell: context band, light sidebar, "Plateforme" chip.
  • Guest shell Sign-in and other guest pages: centred card, flash messages top-end, footer.
